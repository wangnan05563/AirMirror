## 02 构建配置与踩坑

改动仅两处，均未触碰业务代码：

1. `D:\code\otherProjects\AirMirror\app\build.gradle.kts`
   - release：`isMinifyEnabled = true`
   - release：`isShrinkResources = false`
   - `proguardFiles(getDefaultProguardFile("proguard-android-optimize.txt"), "proguard-rules.pro")`
   - debug 配置不变
2. `D:\code\otherProjects\AirMirror\app\proguard-rules.pro`（新增）
   - 只保留 `SourceFile,LineNumberTable`
   - `-renamesourcefileattribute SourceFile`
   - 未使用整包 `-keep`，避免把“未混淆”伪装成优化

实际构建命令：

```powershell
$env:JAVA_HOME='D:\code\Java\zulu17.52.17-ca-jdk17.0.12-win_x64'
$env:ANDROID_HOME='E:\Android\sdk'
$env:GRADLE_USER_HOME='D:\code\Data_Gradle'
.\gradlew.bat :app:assembleRelease --offline --no-daemon --no-watch-fs `
  --project-cache-dir C:\Temp\AirMirrorGradleCache --console=plain
```

踩坑与处理：

- `isShrinkResources=true` 首轮在 `mergeReleaseResources` / AAPT2 报资源路径不存在与 link 异常；改回 `false` 并清理 `release/build/app/intermediates|outputs` 后成功。资源裁剪留作后续单独处理，不在本轮强行打开。
- 构建期间 Gradle daemon 发生 native malloc 崩溃（`Chunk::new`，`hs_err_pid20612.log`），与 Android 模拟器同时运行、内存紧张有关。
- `-Xmx4096m` 直接触发 Windows `os::commit_memory ... DOS error/errno=1455`；改用默认 2048m、先停模拟器后构建成功，release 构建耗时 **17m23s**。
- 因此本机做 release 构建时不要同时跑 Android 模拟器；这是构建环境约束，不是 APK 运行时问题。

## 04 PSS 基线

采样方式：ReceiverActivity 前台 idle，`adb shell dumpsys meminfo io.github.wangnan05563.airmirror`，约每 30 秒一点，共 6 点；不是 30 分钟 soak。

| 时间（秒） | 未优化总 PSS（KB） | 优化后总 PSS（KB） |
| ---: | ---: | ---: |
| 0–18 | 40,409 | 31,145（2s，冷启动后低值） |
| 33–60 | 40,625 | 40,303 |
| 64–95 | 40,416 | 39,503 |
| 95–129 | 39,057 | 41,015 |
| 127–162 | 39,954 | 40,227 |
| 160–193 | 32,754 | 41,203 |
| 均值 | 40,542 | 40,683 |

- 优化后总 PSS 在预热后稳定在 **39.5–41.2 MB**，均值 40,683 KB；未优化均值 40,542 KB，差 +141 KB（+0.35%）。**总 PSS 没有可宣称的下降**。
- 优化后 Native Heap 约 **8.7–9.5 MB**（未优化约 18–20 MB），Java Heap 约 **4.4–5.2 MB**；native 的下降被 Java/其他占用抵消，不能把单项下降当作端到端内存收益。
- 冷启动后首个 2 秒点（31,145 KB）不能作为稳态基线；基线取 33 秒后的 5 点。
- 这组数据只能作为“接收端 idle 短时基线”，不能替代 AC-09 的 30 分钟 soak、真实电视/盒子或 API22 设备数据。

原始样本：

- 优化后原始 CSV（含 Java/Native 分项）：`docs/assets/t06123-20261124/pss-optimized.csv`
- 未优化原始 CSV `C:\Temp\t06123_pss_baseline4.csv` 已随临时目录清理丢失；上表六个总 PSS 点是执行时记录值，未保留 Java/native 分项，故不补造原始文件。

## 05 未完成与边界

1. **PC→优化包握手/首帧未复验**：`release\build\pc-client\install\pc-client\bin\pc-client.bat` 在清理后不存在；执行 `:pc-client:installDist` 重建成功，但本轮未启动到连接阶段（需要 Receiver 6 位码），因此 R8 是否影响协议/首帧仍未知。不能引用优化前的 21 帧/15 秒作为优化包证据。
2. **PSS 不是 AC-09 结论**：只有 2–3 分钟 idle 样本；30 分钟 soak、丢帧、首帧延迟、真实设备温度/功耗均未测。
3. **API22 / Android 7–14 矩阵未覆盖**：仅在 API34 模拟器验证；`airmirror_legacy`（API29）此前因 qcow2 `overlap-check` 无法 boot，API22 兼容性仍未验证。
4. **R8 反射风险未全量排除**：只抽查 Main/Receiver；网络、二维码解析、JCodec、TrustRegistry 等路径未在混淆包上跑全量测试。
5. **`isShrinkResources` 未启用**：资源裁剪单独失败，当前只做代码 shrink；后续若打开需单独处理 AAPT2 资源合并。
6. **测试环境污染**：`airmirror_ui2` 被 harness 类应用抢占，UI 截图和 PSS 的可重复性有限；已尝试创建干净 AVD `airmirror_t06123`，但其启动未在本次采样窗口内完成，正式复验应使用干净设备。

## 06 结论与下一步

- **体积门：通过**。Release APK 从 5,404,397 B 降至 2,395,358 B，相对 T06127 基线减少 2,943,547 B，远低于 +2MB 门限；包信息与签名一致。
- **内存：建立短时基线，不宣称优化收益**。优化包稳态总 PSS 约 40 MB，与未优化包基本持平；native heap 下降是观察项，不是验收结论。
- **建议**：保留 `isMinifyEnabled=true` / `isShrinkResources=false` 作为当前可复现配置；T06124 安全验证、T06125 30 分钟 soak 前，必须先在干净设备上补 PC→优化包握手/首帧，并对 R8 包跑全量单测/关键链路回归。
