# AirMirror GitHub 同款产品调研与优化需求

> 版本：2026-11-21  
> 范围：Android TV 接收端、Android 手机发送端、Windows PC 发送端、访客 Web 入口  
> 方法：GitHub 公开仓库 README / LICENSE + 本项目源码与 2026-11-20 UI 实测基线；不以 star 数排序，不把单个 issue 当普遍结论

## 一、结论先行

1. **AirMirror 的差异化不是再做一个投屏协议，而是“无账号、无广告、局域网优先 + Android/PC 双发送端 + 访客免装”。** 这三点在 GitHub 同类项目中仍是稀缺组合，应继续守住。
2. **直接竞品已经把 Android TV 接收端做成“多协议 + 媒体中心 + 隐私控制 + 运行统计”。** CastBay、PhairPlay 都同时支持 AirPlay 与 DLNA，提供 PIN/密码/设备白名单、字幕音轨、播放统计和多语言；AirMirror 目前只有私有协议 + DLNA 媒体推送，单协议会限制新用户进入。
3. **当前最大的体验断点不在“能不能投”，而在“第一次失败后不知道怎么办”。** 无设备空态、电视端输入、质量可见性、信任设备管理、PC 端安装与音频，是下一版最该收口的五件事。
4. **UI 不需要推倒重来。** 2026-11-20 的 360dp 全页面实测已达 94/100、22 项用例通过；升级重点应是 TV 十英尺布局、空态/错误态、设备卡、控制条和主题变体，而不是换一套皮肤。
5. **主题升级先做“令牌化 + OLED 纯黑 + 高对比”，浅色主题放 P2 并单独做品牌决策。** TV 端继续以深色为唯一基调，避免破坏已冻结的视觉识别。

本次共梳理 **39 项需求**：P0 9 项、P1 20 项、P2 10 项。

### 2.1 四类竞品给出的不同答案

- **Android TV 直接竞品（CastBay / PhairPlay）**：把“接收端”做成家庭媒体入口。它们的共同能力是 AirPlay + DLNA 双协议、4K/HEVC、字幕音轨、PIN/密码/白名单、播放统计、多语言。AirMirror 的私有协议在 Android/PC 发送端更可控，但需要补上“iPhone/Mac 用户零门槛进入”的协议缺口。
- **Android→PC 工具（scrcpy / QtScrcpy）**：把“低延迟 + 可控制 + 多设备”做到极致，但要求 USB 调试或 ADB，无法覆盖普通家庭用户。AirMirror PC 端应学它的“键鼠/多设备/录制”，不能学它的“先装驱动再连接”。
- **浏览器/近场工具（Deskreen / LocalSend）**：证明“免安装”和“局域网直传”是强拉新入口。AirMirror 已有访客上传，但只到“传文件”，还没到“浏览器直接投屏/互传”。
- **媒体协议工具（go2tv / UxPlay）**：把 DLNA/AirPlay 的控制面做得很细——字幕、音轨、播放列表、PIN、设备白名单、FPS 统计。AirMirror 的 DLNA 目前偏“能推”，还没到“好控制”。

### 2.2 可直接借鉴与不能照搬

**可借鉴**
- CastBay 的“遥控器向下拉出媒体菜单”：播放统计、画面比例、音轨/字幕、暂停/跳转放在同一层，不打断画面。
- PhairPlay 的“协议开关 + 访问控制 + 多语言”三件套：把“谁能投、投什么协议”变成设置项，而不是写死。
- UxPlay 的“PIN/密码/allow-block/信任注册”：共享网络里，默认信任已知设备，陌生人必须确认。
- LocalSend 的“近场发现 + 手动 IP + 收藏”：发现失败时永远有一条手动兜底路径。
- Deskreen 的“二维码/URL + 自定义 IP”：访客入口不依赖安装 App，二维码要带当前有效 IP。
- Sunshine 的“Web UI 配置/配对”：PC 端可以把设置、配对、日志放进本地 Web 控制台，减少原生 UI 成本。

**不能照搬**
- 不把 GPL/AGPL 代码直接并入 Apache-2.0 的 AirMirror；AirPlay 只能走“许可证兼容的 SDK / 清洁室实现 / 独立进程边界”，并先过法务。
- 不做桌面端的“参数海洋”。AirMirror 的 TV/手机主路径应保持 2 个决策以内，进阶参数收进“高级/诊断”。
- 不做 torrent、直播源、盗链、DRM 解密；这类能力会把产品拖进内容合规风险。
- 不承诺第三方 Miracast 接收：Android 8.0+ 第三方 APK 无法注册系统级 WFD sink，PRD 已把 Miracast 移出 P0。

## 三、AirMirror 现状基线

- **功能基线**：PRD v1.1 定义 14 个 FR；FS-01/02/03/06/07/08/09/10/11/13 已实现，FS-04/05/12 目前只有单元测试和部分代码，FR-14 的 PC 发送端只完成“视频 + 手动 IP + 投屏码”，无音频、无 mDNS、无二维码、无安装包。
- **UI 基线**：2026-11-20 在 E 盘 360×640dp 模拟器完成三轮“实测—修复—回归”，22 个 UI 用例通过，综合 94/100；首启、接收端、设置、主入口、发送端、关于、更新弹窗均已收口。
- **主题基线**：`Theme.kt` 已把颜色、字号、圆角、间距收成常量，但仍是一套深色；没有主题注册、切换、OLED/高对比变体，也没有主题截图回归。
- **信任基线**：`TrustRegistry` 已有信任设备记录和 `revoke()`，但 UI 没有“信任设备中心”；没有 PIN/密码/allow-block 模式。
- **入口基线**：访客 Web 目前是“上传图片/文件”，不是浏览器镜像；PC 端是命令行/简易 GUI，未形成安装—发现—配对—投屏的完整闭环。
- **协议基线**：私有协议 + DLNA 媒体推送；无 AirPlay、无 Google Cast、无 Miracast 接收。

## 五、优化需求

优先级定义：P0 = 下一版必须收口，直接影响首次成功率/信任；P1 = 3–6 个月补齐，拉平直接竞品；P2 = 战略/可选，需过决策门。成本用 S/M/L/XL 表示，仅用于排序，不是工期承诺。

### 5.1 客户体验（CX）

| ID/优先级 | 需求与现状断点 | 目标与验收 | 成本 | 依赖 |
|---|---|---|---|---|
| CX-01 / P0 | **空态与网络自检**。无设备时只有“正在搜索…”，用户不知道是网络、AP 隔离、接收端没开，还是权限问题。 | 空态必须给出“最可能原因 + 3 个动作”：重试、扫码、网络诊断/教程；显示本机 IP、网络类型、接收端在线状态。360dp 与 1080p 无截断，错误可复现。 | M | 网络探测、ErrorNotice |

## 六、优先级与路线

### Wave 1：可用性收口（P0）

- CX-01 空态与网络自检、CX-02 首次投屏 2 步
- FE-01 PC 音频、FE-02 PC 发现/配对/安装、FE-04 访问控制与信任中心
- UI-01 TV 十英尺布局、UI-02 空态/错误/加载
- TH-01 主题令牌 v2
- EN-01 性能预算与首帧 SLO

**出口标准**：同一局域网首次投屏成功率 ≥95%（目标值，需实测）；无设备空态不再出现“只有一行正在搜索”；PC 端安装后 2 分钟内能出声出画；电视上能看到“谁在投、怎么停”。

### Wave 2：能力补齐（P1）

- PC：FE-03 WGC/多显示器/隐私窗口、UI-07 PC 客户端
- 媒体：FE-05 文件/文本互传、FE-06 DLNA 控制增强
- 体验：CX-03 HUD、CX-04 手机键盘/遥控、CX-05 诊断导出、CX-06 多语言、CX-07 隐私可见
- UI：UI-03 设备卡、UI-04 控制条、UI-05 设置 IA、UI-06 首启 v2、UI-09 图标/动效
- 主题：TH-02 OLED/高对比、TH-05 主题 QA
- 底座：EN-02/03/04

**出口标准**：PC 端具备“安装—发现—配对—投屏—排障”闭环；手机/PC/访客三端都能传文件；DLNA 媒体有字幕/音轨/进度；三套主题通过截图与对比度矩阵。

### Wave 3：生态扩展（P2，需过决策门）

- FE-07 AirPlay、FE-08 Google Cast
- FE-09 一投多屏、FE-10 会话接力
- FE-11 待机氛围屏、FE-12 浏览器镜像、FE-13 录制/截图
- UI-08 访客 Web v2、TH-03 浅色主题、TH-04 Web 主题同步

**决策门**
- **G1 AirPlay**：法务确认 FairPlay/专利/许可证边界；技术确认原生库 ABI、性能、可维护性；不通过则不做，不用 GPL 代码硬拼。
- **G2 Cast**：确认 Google Cast 认证成本与品牌规范；只做媒体投播，不承诺全屏镜像。
- **G3 浅色主题**：品牌负责人确认是否允许手机/PC 浅色；TV 不受影响。
- **G4 文件互传**：确认产品边界（是否做“投屏版 AirDrop”）、存储权限、内容安全责任。
- **G5 一投多屏**：确认目标场景（会议/教室）与网络前提；家庭单屏不做。

## 七、不做清单

- 不做账号体系、云中转、广告、默认遥测；保持局域网优先、无账号。
- 不做 DRM 解密、盗链、直播源、torrent；不碰内容版权灰区。
- 不承诺第三方 Miracast 接收；Android 8.0+ 第三方 APK 无法注册系统 WFD sink。
- 不为了“功能多”把主路径做成参数海洋；进阶能力收进“高级/诊断”。
- 不把 GPL/AGPL 代码直接并入 Apache-2.0 仓库；协议扩展必须先过许可证门。

## 八、待确认

1. AirPlay 是 P1 战略投入，还是只做“DLNA + 私有协议”差异化？这决定 Wave 3 是否启动。
2. 文件互传是否在 AirMirror 产品范围内？若做，是“投屏附属”还是独立入口？
3. 浅色主题是否允许在手机/PC 出现？TV 是否永远深色？
4. 目标硬件下限：Android 7 / 1GB RAM / armv7 是否仍在支持范围？这会影响 AirPlay/4K/多屏的可行性。
5. 4K/HDR 是卖点还是“尽力而为”？当前 B 级盒子最高 1080p60，先把 1080p60 稳到 30 分钟不降档，再谈 4K。
