# AirMirror M2 联调与 Win 测试（T06115）

- 日期：2026-11-24
- 结论：**部分通过，不能判定 AC-04 / AC-05 通过，T06115 仍阻塞。**
- 本轮只做本地可执行的真实链路验证，不改产品代码，不把模拟器结果冒充 Win10 + Win11 + 物理电视验收。

## 1. 测试环境

| 角色 | 实际环境 |
| --- | --- |
| PC 发送端 | Windows 10.0.19045，x64；PC client `:pc-client:installDist` |
| Android 接收端 | Android 14（API 34）模拟器 `sdk_gphone64_x86_64`，720×1280 显示覆盖 |
| 连接方式 | `adb forward tcp:41523 tcp:41523`，PC 连 `127.0.0.1:41523`；**不是同网 mDNS 发现** |
| 音视频编码 | 未安装 FFmpeg，回退 JCodec；1280×720@15 请求，实测 1.8–2.4fps |

## 2. 已通过的部分

### 2.1 PC 运行时自检

```text
AIRMIRROR_PC_SELF_CHECK_OK version=17.0.12 os=Windows 10 arch=amd64
```

### 2.2 接收端首启与待连接页

- 接收端首启向导可跳过，进入待连接页。
- 页面显示设备名 `sdkgphone64x-07`、投屏二维码、6 位投屏码与“60 秒后更换”提示。
- 说明：模拟器里同时存在其他测试 APK；本轮关闭了 `com.emoreply.*`、`com.quietsentry.app` 及无障碍服务后，接收端页面可正常操作。这属于测试环境污染，不是 AirMirror 缺陷。

### 2.3 错误投屏码负向路径

用旧码连接，PC 端准确报错并 3 秒重试：

```text
[status] 连接 127.0.0.1:41523 …
[status] 连接中断：投屏码不正确：握手校验与大屏当前码对不上，请重新读码；若反复如此，检查连线是否被替换；3 秒后重连
```

证据：`docs/assets/m2-win-20261124/pc-wrong-code-rejected.log`

### 2.4 正确投屏码的握手、授权与首帧

PC 端读取接收端当前码后连接成功：

```text
[status] 连接 127.0.0.1:41523 …
[status] 握手成功 v1，对方=sdk_gphone64_x86_64，已加密
[status] 已授权，开始采集 1280x720@15
[status] 未找到 FFmpeg，回退 JCodec（低帧率）：1280x720@15
[stats] frames=1 fps=0.8 encode=827ms
[stats] frames=21 fps=1.8 encode=375ms
```

- HELLO/AUTH 握手成功，`secure=true`，设备名正确。
- 15 秒内送出 21 帧，无崩溃、无断连。
- **不能当作 1080p30 验收**：JCodec 软件编码只有约 2fps。

证据：`docs/assets/m2-win-20261124/pc-android14-handshake-first-frames.log`

### 2.5 防火墙脚本静态验证

```text
ADMIN=true
RULES=0
DETAIL=缺少 AirMirror 专用网络入站规则
WOULD_CREATE name=AirMirror PC (TCP 41523) ... profile=Private
WOULD_CREATE name=AirMirror PC (UDP 41524-41525) ... profile=Private
WOULD_REMOVE name=AirMirror PC (TCP 41523)
WOULD_REMOVE name=AirMirror PC (UDP 41524-41525)
```

脚本路径与提示逻辑存在，`-Check`/`-DryRun` 可复核。但当前 Win10 **实际规则数为 0**，真实局域网发现大概率会被防火墙阻断。

## 4. 本轮发现

| ID | 级别 | 状态 | 说明 |
| --- | --- | --- | --- |
| T06115-D1 | P1 | 待处理 | 当前 Win10 防火墙规则 `RULES=0`；真实同网发现前必须完成向导放行或安装时创建规则。需要实际验证阻断提示，而不是只看脚本。 |
| T06115-D2 | P1 | 待处理 | PC 分发包未带 FFmpeg，JCodec 回退只有约 2fps；发布包必须内置 FFmpeg，否则 1080p30 不达标。 |
| T06115-D3 | P2 | 测试口径 | 本轮是 adb 转发到模拟器，证明协议/授权/首帧可用，但不等于同网发现与物理电视验收。 |
| T06115-D4 | P2 | 待验证 | 模拟器混入其他测试 APK/无障碍服务，会抢占前台；测试机应使用干净镜像，避免误判。 |

## 5. 复测所需条件

1. Win10 与 Win11 各一台，具备管理员权限。
2. 一台物理 Android TV 或电视盒子，与 PC 在同一局域网，接收端可安装。
3. 可安装的 PC ZIP（含 `install.ps1`、`fix-firewall.ps1`、`uninstall.ps1`、FFmpeg）。
4. 依次执行：
   - 安装计时 → 首启向导 → 同网发现计时 → 投屏码配对 → 首帧计时；
   - 接收端 PIN 模式 + 重启后验证；
   - 接收端撤销信任，确认进行中的 PC 会话立即断开；
   - 卸载后检查程序目录、快捷方式、HKCU 卸载项、防火墙规则残留。
5. 30 天信任过期用“修改接收端时钟/测试注入”方式验证，不能等真实 30 天。

## 6. 结论

- 本轮拿到 **PC→Android 14 接收端真实握手、加密、授权、首帧**证据，负向投屏码也正确拒绝。
- 但 AC-04 的安装/发现/卸载和 AC-05 的 30 天/PIN/撤销均未验证；也没有 Win11 与物理电视。
- **T06115 不能按“通过”回传，保持阻塞，等待测试硬件。**
