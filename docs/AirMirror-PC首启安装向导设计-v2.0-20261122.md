# AirMirror PC 首启安装向导设计 v2.0（T06108 / REQ-004）

| 项 | 内容 |
| --- | --- |
| 任务 | T06108 [PRD] 设计 PC 安装向导 |
| 需求 | REQ-004：mDNS 自动发现、二维码/投屏码配对、记忆设备；交付 ZIP+脚本（无签名时），含首启向导；Win10/11 验证 |
| 当前实现 | `pc-client` Swing 单页：IP、端口、投屏码、设备名、画质 + 开始/停止 + 日志，无首启向导、无发现、无错误指引 |
| 产物性质 | PC UI 设计稿与实现约束；本单不写代码，供 T06109/T06110/T06111 实施 |
| 视觉基线 | Midnight 主题（`docs/AirMirror-主题令牌结构-v2.0-20261122.md`），PC 采用 1280×800 默认窗口 |

## 01 结论先行

1. 首启向导是 **PC 应用内的四步向导**，不另做安装器；ZIP 解压后运行 `AirMirror-PC.bat`，首次启动自动进入向导。
2. 四步固定为：**网络检查 → 防火墙 → 发现设备 → 投屏验证**。每步只做一件事，可跳过、可返回，但跳过必须留下状态标记。
3. 每步都有明确成功态、检查中态、失败态和下一步按钮；失败不展示 Java 堆栈，只展示“发生了什么 + 下一步”。
4. 发现优先 mDNS，失败自动降级到 UDP 广播/手动 IP；二维码与 6 位投屏码并列，不隐藏手动入口。
5. 首次投屏目标 ≤2 分钟：默认路径 4 次点击内完成；网络/防火墙检查各 ≤10 秒，发现 ≤3 秒出首台设备。
6. 卸载只删除程序目录与用户选择保留的配置；不写注册表自启、不留防火墙规则。卸载脚本先撤销自己创建的规则。

首次启动判定：配置目录不存在 `onboarding.json` 或 `completed=false`。完成向导写入 `completed=true`、`completedAt`、`networkStep`、`firewallStep`、`lastDeviceId`。

## 03 四步流程

### 3.1 第 1 步：网络检查

**目的**：确认 PC 有可用网络、不是仅回环、能访问局域网。

| 状态 | 界面 | 文案 | 动作 |
| --- | --- | --- | --- |
| 检查中 | 进度条 + 网卡名 | “正在检查网络…” | 无 |
| 成功 | 绿色勾 + 当前网段 | “网络正常 · 192.168.50.x” | 下一步 |
| 无网络 | 黄色警示 | “没有检测到网络，先连 Wi-Fi 或网线” | 重新检查 / 跳过 |
| 仅回环 | 红色 | “只找到回环地址，无法发现电视” | 打开网络设置 / 重新检查 |
| 多网卡 | 下拉选择 | “选择用于投屏的网卡” | 下一步 |
| 被 VPN 接管 | 黄色 | “VPN 可能隔离局域网，投屏可能失败” | 仍要继续 / 打开设置 |

验收：网卡枚举 ≤2 秒；默认选中默认路由网卡；不读取用户浏览记录、不探测外网。

### 3.2 第 2 步：防火墙

**目的**：Windows Defender 防火墙拦截入站/出站时给出可执行脚本，不一直“搜索中”。

| 状态 | 界面 | 文案 | 动作 |
| --- | --- | --- | --- |
| 未检查 | 说明卡 | “AirMirror 需要局域网发现与投屏端口” | 开始检查 |
| 已放行 | 绿色勾 | “防火墙已放行 AirMirror” | 下一步 |
| 被拦截 | 红色 + 命令预览 | “防火墙拦截了设备发现，运行修复脚本后重试” | 复制命令 / 以管理员运行 / 稍后再说 |
| 无管理员权限 | 黄色 | “需要管理员权限；可让管理员运行 scripts\\fix-firewall.ps1” | 复制路径 / 打开脚本目录 |
| 第三方杀软 | 黄色 | “检测到第三方防火墙，请在它的允许列表放行” | 打开帮助 |

脚本规则（T06111 实施）：

```powershell
New-NetFirewallRule -DisplayName "AirMirror PC (TCP 41523)" -Direction Inbound -Protocol TCP -LocalPort 41523 -Action Allow -Profile Private
New-NetFirewallRule -DisplayName "AirMirror PC (UDP 41524-41525)" -Direction Inbound -Protocol UDP -LocalPort 41524-41525 -Action Allow -Profile Private
```

- 只放行 **专用网络**，不放行公用网络。
- 规则名固定，重复执行先删同名再建，保证幂等。
- 卸载脚本 `remove-firewall.ps1` 按 DisplayName 删除；失败不阻断卸载，只记录日志。
- UI 不直接提权；用户点击“以管理员运行”后才启动 PowerShell，并显示 UAC 说明。

### 3.3 第 3 步：发现设备

**目的**：3 秒内给出至少一台电视；没有则进入可诊断空态。

| 状态 | 界面 | 文案 | 动作 |
| --- | --- | --- | --- |
| 搜索中 | 雷达动画 + 已用时长 | “正在同一网络里找电视…” | 取消 |
| 已发现 | 设备卡列表 | “找到 2 台设备” | 选择设备 |
| 无结果 | 诊断卡 | 按原因给文案 | 重试发现 / 用投屏码 / 手动 IP |
| mDNS 被禁 | 黄色提示 | “路由器屏蔽了设备发现，已改用广播继续找” | 不打断 |
| 多台在线 | 列表 | “选择要投屏的电视” | 必须选择，禁止静默连接 |
| 接收端离线 | 灰卡 + 重试 | “这台电视离线，可能刚关机或换网” | 重试 / 换设备 |
| AP 隔离 | 红色诊断 | “网络禁止设备互访，关闭 AP 隔离或用投屏码” | 重试 / 用投屏码 / 手动 IP |

发现顺序：mDNS `_airmirror._tcp` → UDP 广播 41524 → 定向单播 41525 → 手动 IP。每路独立计时，任一路命中即展示；组播失败但广播命中不提示，保持静默降级。

### 3.4 第 4 步：投屏验证

**目的**：在 2 分钟内完成第一次投屏，并验证画面/声音/延迟。

| 状态 | 界面 | 文案 | 动作 |
| --- | --- | --- | --- |
| 待配对 | 二维码 + 6 位码 | “在电视上确认投屏码” | 输入码 / 扫码 |
| 配对中 | 进度 | “正在配对…” | 取消 |
| 等待大屏确认 | 倒计时 | “请在电视上点允许（5 秒无操作自动允许）” | 取消 |
| 首次画面 | 预览缩略图 + 统计 | “已连接 · 1080p30 · 延迟 180ms” | 完成 |
| 黑屏/无画面 | 诊断 | “接收端画面未就绪，点亮电视或回到 AirMirror” | 自动恢复 / 重试 |
| 音画不同步 | 黄色 | “声音和画面有偏差，正在重新对齐” | 自动恢复；持续则“改用兼容模式” |
| 编码失败 | 红色 | “当前显卡不支持 H.264，已回退兼容编码” | 继续 / 降低画质 |
| 码错误/过期 | 红色 | “投屏码不正确/已过期，2 秒内重试或刷新” | 刷新码 / 重试 |

完成条件：首帧出现、连续 3 秒稳定、统计面板显示分辨率/帧率/延迟；三个条件都满足才写 `completed=true`。用户可“先跳过，进主界面”，但主界面顶部保留“完成设置”入口。

## 04 主界面改造

### 4.1 布局

```text
┌──────────────────────────────────────────────┐
│ AirMirror PC        [设备列表] [二维码] [设置] │
├──────────────────────────────────────────────┤
│ 设备卡：客厅电视  在线  1080p    [投屏]        │
│ 设备卡：卧室电视  离线  上次 11-20 [重试]      │
├──────────────────────────────────────────────┤
│ 或用投屏码： [ 6 位输入 ]  [连接]  [刷新]       │
│ 或手动 IP：  [ 192.168.50.223 ] [端口 41523]   │
├──────────────────────────────────────────────┤
│ 状态：未连接   画质 [1080p30 ▼]  [开始投屏]    │
│ 诊断日志（折叠）                              │
└──────────────────────────────────────────────┘
```

- 默认窗口 1280×800，最小 960×640；高 DPI 按 125%/150% 缩放。
- 设备列表最多首屏 5 张卡，超出滚动；每张卡显示名称、在线、分辨率、最近使用。
- 二维码与投屏码同屏，不藏在二级页；扫码成功直接进入配对确认。
- 诊断日志默认折叠；错误态自动展开最近 20 行，提供“复制诊断信息”。

### 4.2 状态与文案

复用 Android `ErrorNotice` 的六类：网络、配对、权限、能力、会话、片源。PC 端只增加三类平台特有：

| Cause | 首行 | 下一步 |
| --- | --- | --- |
| `FIREWALL_BLOCKED` | 防火墙拦截了发现 | 运行修复脚本后重试 |
| `NO_ADMIN` | 需要管理员权限 | 让管理员运行修复脚本 |
| `ENCODER_FALLBACK` | 已回退兼容编码 | 降低画质或继续 |

首行 ≤18 字；禁止“投射/同屏/共享”；日志区可保留技术细节，主提示不出现堆栈、异常类名、端口号裸值。

| 场景 | 触发 | 主文案 | 首选动作 | 次选动作 |
| --- | --- | --- | --- | --- |
| 无网络 | 网卡枚举为空 | 没有检测到网络 | 打开网络设置 | 跳过 |
| 仅回环 | 只有 127.0.0.1 | 只找到回环地址 | 重新检查 | 手动 IP |
| 防火墙拦截 | 入站探测超时 + 规则缺失 | 防火墙拦截了发现 | 以管理员运行修复 | 稍后再说 |
| 无管理员 | PowerShell 退出 5 | 需要管理员权限 | 复制脚本路径 | 跳过 |
| 发现为空 | 三路 3 轮无命中 | 列表里没有设备 | 重试发现 | 用投屏码/手动 IP |
| AP 隔离 | 同网段 + 三路无命中 | 网络禁止设备互访 | 关闭 AP 隔离 | 用投屏码 |
| 双频分离 | 缓存地址跨网段 | 电脑和电视不在同一频段 | 连同一 Wi-Fi | 手动 IP |
| 多台在线 | 发现 ≥2 台 | 选择要投屏的电视 | 选卡 | 刷新 |
| 接收端离线 | 上次设备心跳失败 | 这台电视离线 | 重试 | 移除记忆 |
| 码过期 | 服务端返回 EXPIRED | 投屏码已过期 | 刷新码 | 重试 |
| 码错误 | 服务端返回 WRONG | 投屏码不正确 | 重试 | 刷新码 |
| 配对拒绝 | 大屏点拒绝 | 大屏拒绝了投屏 | 等一分钟再试 | 换设备 |
| 黑屏 | 已连接无首帧 | 接收端画面未就绪 | 自动恢复 | 重试 |
| 音画偏差 | 连续 3 帧超阈值 | 声音和画面有偏差 | 自动对齐 | 兼容模式 |
| 编码失败 | 硬编初始化失败 | 已回退兼容编码 | 继续 | 降低画质 |
| 端口占用 | bind 41523 失败 | 投屏端口被占用 | 换端口 | 关闭占用程序 |

## 07 打包与安装

- 产物：`AirMirror-PC-<version>-win-x64.zip`，解压即用，不写系统目录。
- 目录：
  ```text
  AirMirror-PC/
  ├─ AirMirror-PC.bat
  ├─ app/                # runtime + jars
  ├─ ffmpeg/             # ffmpeg.exe + DLL
  ├─ scripts/
  │  ├─ fix-firewall.ps1
  │  ├─ remove-firewall.ps1
  │  └─ uninstall.ps1
  ├─ README.txt
  └─ VERSION
  ```
- 无代码签名时，首次运行 SmartScreen 提示：README/向导第一屏说明“更多信息 → 仍要运行”，不伪造签名。
- 卸载：停止进程 → 删除防火墙规则 → 删除程序目录；询问是否保留 `%APPDATA%\AirMirror` 配置，默认保留。
- 不创建开机自启；用户可在设置里手动开启，卸载时删除该自启项。

## 08 验收与埋点

| 指标 | 目标 | 采集点 |
| --- | --- | --- |
| 首次投屏 | ≤2 分钟 | 向导开始 → 首帧出现 |
| 同网发现 | ≤3 秒出首台 | 搜索开始 → 第一台设备卡 |
| 防火墙修复 | ≤30 秒 | 点击修复 → 规则存在 |
| 卸载残留 | 0 条规则/0 自启 | 卸载后 `Get-NetFirewallRule` 与注册表检查 |
| 错误反馈 | ≤2 秒 | 服务端错误码 → 主提示更新 |
| 主提示可读 | 首行 ≤18 字 | 文案表静态检查 |

埋点只写本地 `%APPDATA%\AirMirror\telemetry.jsonl`：`wizard_step`、`step_result`、`elapsed_ms`、`cause`、`action`；不上传、不包含 IP/设备名/投屏码。
