# AirMirror TV 布局改造（T06103）

> 任务：T06103《改造 TV 布局逻辑》，关联 PRD UI-01、REQ-006、REQ-023。
> 结论：在 T06100 的 TV 判定/5% 安全区基础上，补齐二维码按屏宽 160/200/240dp 分档、
> 21:9 兼容、20 字符长设备名不重叠，以及配对确认/结束确认/设置/首启/入口页的
> 显式 D-pad 焦点链与返回键行为。本任务不包含 4K 硬验收，真机 overscan/D-pad/TalkBack
> 仍由 T06115 现场复验。

## 1. 本轮差距与改造口径

| 差距 | T06100 现状 | T06103 改造 |
| --- | --- | --- |
| 二维码基准 | 手机/TV 共用 156/190dp 基座，仅按屏高 34% 收敛 | TV 先按屏宽取 160/200/240dp，再受屏高 34% 上限约束；手机口径不变 |
| 超宽屏 | 未覆盖 21:9 | 2560×1080 下安全区 128/54px、二维码 368px、二维码与投屏码并排 |
| 长设备名 | 只验证常规名字 | 20 字符两行内，与右上“显示设置”和二维码均不重叠 |
| 配对确认 | 确认条出现后焦点仍可能留在底层设置入口 | 默认焦点落“拒绝”，左右串“拒绝↔允许”，返回键等价拒绝 |
| 结束确认 | 默认焦点未显式 | 默认焦点落“取消”，左右串“取消↔结束”，返回键等价取消 |
| 设置页 | 行靠在布局顺序/几何搜索 | 每次刷新按可见控件重串纵向链，关闭后焦点回“显示设置” |
| 首启 | 每步焦点未收回 | 每步“跳过全部→当前主控件→下一步”，底部按钮左右串链；切步/返回后焦点回下一步 |
| 入口页 | 焦点依赖深度优先顺序 | `chainVisible` 按视觉顺序串“投屏→接收→数据边界→关于” |

## 2. 二维码自适应

`TvLayoutSpec.tvQrBaseDp(widthPx)` 按屏宽分档：

| 屏宽 | 基准 dp | 说明 |
| --- | --- | --- |
| <1280px | 160dp | 低分辨率 TV/盒子，避免沿用手机 190dp 后偏大或偏小 |
| 1280–1919px | 200dp | 720p 档 |
| ≥1920px | 240dp | 1080p/21:9 档 |

`tvQrSidePx(widthPx, heightPx, density)` 再取 `min(基准dp × density, 屏高 × 34%)`。320dpi 下：

| 分辨率 | 基准 | 34% 屏高上限 | 实际边长 |
| --- | --- | --- | --- |
| 1920×1080 | 240dp=480px | 368px | 368px（保持 T06100） |
| 1280×720 | 200dp=400px | 245px | 245px（保持 T06100） |
| 1024×768（4:3） | 160dp=320px | 262px | 262px（保持 T06100） |
| 2560×1080（21:9） | 240dp=480px | 368px | 368px |

低密度电视（1080p、density=1）由旧的 190px 提升到 240px，不再被手机基座压小；
320dpi 三档像素未变，T06100 的截图与安全区断言保持等价。

## 3. 焦点链与返回键

### 3.1 配对确认 `promptBar`

1. 显示后 `promptDeny.requestFocus()`，默认焦点在“拒绝”，避免误触允许。
2. `promptDeny ↔ promptAllow` 左右串链；确认条在底部，遥控器左右即可选择。
3. 返回键等价拒绝：`respondToPrompt(false)`，收起确认条并把焦点送回“显示设置”入口。
4. 焦点态背景由 `TvFocus` 统一接管：聚焦时先清空 `MaterialButton` 的 `backgroundTintList`，
   再画 2dp 高对比描边；失焦恢复原背景与 tint，避免按钮底色把描边盖掉。

### 3.2 结束确认 `endBar`

1. 显示后 `endCancelButton.requestFocus()`，默认焦点在“取消”。
2. `endCancelButton ↔ endConfirmButton` 左右串链。
3. 返回键等价取消：`cancelEndConfirm()`，10 秒倒计时由 ticker 收口，焦点回设置入口。

### 3.3 显示设置

1. `refreshSettings()` 先刷新模式/开关/画质/信任行，再 `TvFocus.chainVisible(settingsPanel)`
   按当前可见控件深度优先重串纵向链，动态新增的画质档位和信任条目不会漏。
2. 打开设置时焦点落当前选中模式行；关闭后焦点回右上“显示设置”。
3. 设置面板是非全屏覆盖层，保留 5% 安全区，避免电视 overscan 吃掉行首行尾。

### 3.4 首启三步

| 步骤 | 主控件 | 纵向链 |
| --- | --- | --- |
| 1 局域网访问 | 下一步 | 跳过全部 → 下一步 |
| 2 后台运行/自启 | 自启开关 | 跳过全部 → 自启开关 → 下一步 |
| 3 设备名 | 输入框 | 跳过全部 → 输入框 → 下一步 |

底部可见按钮按“上一步→跳过→下一步”左右串链；切步或返回上一步后，焦点统一收回
当前步骤的“下一步”，避免原控件隐藏后焦点悬空。

### 3.5 返回键优先级

`onBackPressed` 按覆盖层从高到低处理：

1. 设置面板 → 关闭面板；
2. 首启（step>1）→ 回上一步；
3. 配对确认 → 等价拒绝；
4. 结束确认 → 等价取消；
5. 非投屏 → 系统默认退出；
6. 投屏中 → 首次返回弹结束确认，已显示则确认结束。

### 3.6 入口页

`MainActivity` 在 `TvFocus.applyTree(root)` 后调用 `chainVisible(root)`，按视图视觉顺序
串“投屏→接收→数据边界→关于”，不再依赖几何搜索在文案入口间跳。

## 5. 验证

- 定向：`TvLayoutSpecTest` 6 项 + `TvLayoutUiTest` 7 项 + `TvFocusUiTest` 5 项，共 18 项 / 0 失败。
- 受影响回归：`FocusCoverageTest`、`FocusPolicyTest`、`MainVisualGuardTest`、`CodeFadeGuardTest`、
  `PinAccessUiTest`、`TrustSettingsUiTest`、`ErrorStateCardUiTest`、`AccessibilityManifestTest`
  共 45 项 / 0 失败。
- 全量：119 类 / 885 项 / 0 失败 / 0 跳过；T06102 时偶发的 4 项 Windows 临时文件抖动本次未复现。
- Robolectric 没有真实 `ViewRootImpl`，`Activity.currentFocus` 恒为 null；焦点断言改为读取
  `decorView.findFocus()`，并以 TV 模式 `isFocusableInTouchMode=true` 模拟遥控器非触屏环境。
  这两处只影响测试口径与 TV 盒子兼容，不改变手机“触摸不留焦点框”的策略。
- 关键断言：1080p/720p/4:3/21:9 安全区、二维码像素、并排宽度、全页正文 ≥24sp、
  长设备名不重叠、各关键页默认焦点与返回键行为、nextFocus 链方向。
- 证据图：
  - `docs/assets/tv-layout-20261123/tv-layout-1080p-pairing-20261123.png`：1080p 配对确认条；
  - `docs/assets/tv-layout-20261123/tv-layout-21x9-waiting-20261123.png`：2560×1080 待连接页；
  - `docs/assets/tv-layout-20261123/tv-layout-1080p-long-name-20261123.png`：20 字符设备名待连接页。
- 边界：4K 未纳入本轮硬验收；真实电视 HDMI overscan、物理 D-pad、TalkBack 顺序、
  断电重启 PIN 仍由 T06115 现场验收。本任务证明的是 Android 像素布局与焦点链在 JVM/Robolectric
  下可重复，不等价于所有电视硬件表现。

## 6. 与 T06100/T06102 的关系

- 复用 T06100 的 `TvLayoutSpec.isTvLayout`、5% 安全区、码槽 34% 屏高上限与并排阈值，
  不推翻其 320dpi 像素口径。
- 复用 T06102 的语义令牌（背景、面板、强调色、危险色、焦点填充），焦点环仍为 2dp
  高对比描边，不新增颜色字面量。
- T06103 完成后，T06104《开发空态视觉组件》的前置 T06101/T06102/T06103 全部满足，
  可进入下一波。
