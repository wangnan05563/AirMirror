## 02 T06117：PC 系统声音链路

新增 `pc-client/.../pc/audio/`：

| 文件 | 职责 |
| --- | --- |
| `WasapiLoopbackCapture.kt` | JNA 直调 COM：默认渲染端点 loopback、共享/事件驱动、100ms 缓冲、`WAVEFORMATEXTENSIBLE` 解析 |
| `PcmConverter.kt` | 设备混音格式 → 48kHz/双声道/s16；支持 float32/64、16/24/32bit、单声道上混、线性重采样、0–100 增益 |
| `PcAudioFormat.kt` | 线上口径 `sr=48000&ch=2&br=128&enc=aac-lc`、AAC-LC `0x11 0x90`、1024 样本/帧、PTS 计算 |
| `FfmpegAacEncoder.kt` | FFmpeg 子进程只做 AAC-LC 编码，PCM stdin → ADTS stdout |
| `AdtsParser.kt` | 剥 ADTS 头，按 `frame_length` 切裸 AAC 访问单元，支持残帧/垃圾前缀/多帧同块 |
| `AudioSender.kt` | 采集→转换→编码→AUDIO 帧；开关/音量、CONFIG、静音停发、恢复重发 CONFIG 并重置 PTS |

接线：

- `SenderEngine.Config` 增加 `audioEnabled`/`volumePercent`；握手能力按 `ffmpeg != null && WasapiLoopbackCapture.isSupported()` 决定是否带 `AUDIO_AAC`。
- 视频与音频共用 `mediaEpochNanos` 作为 PTS 基准；`SessionControl.OP_AUDIO` 可中途开关。
- `Main.kt` 增加“投送系统声音”复选框、音量滑杆与 `--audio`/`--volume` CLI。
- `pc-client/build.gradle.kts` 增加 `net.java.dev.jna:jna:5.6.0`。

## 03 T06119：本地性能埋点

新增 `app/.../perf/`：

| 文件 | 职责 |
| --- | --- |
| `PerfTrace.kt` | 固定事件名、JSONL 行编码、字段清洗/限长、敏感键 `redacted`、7 天保留口径 |
| `PerfSink.kt` | 单文件 512KB 轮转、最多 8 个文件、过期清理；只碰 `perf-*.jsonl` |
| `PerfLog.kt` | 应用私有 `files/perf/` 同步落盘，无网络上传；`clear()` 供诊断页清空 |

埋点接线：

- `ReceiverSession`：`SESSION_START`、`AUTH`、`CONFIG`、`DROP`（增量）、`FIRST_FRAME`（`config_ms`/`auth_ms`）、`AUDIO_SWITCH`、`AUDIO_OPEN`、`AUDIO_GAP`、`SESSION_END`。
- `ReceiverActivity`：允许/拒绝授权与结束投屏的 `CLICK`。
- `Diagnostics.clearCaches()`：同时清理过期埋点文件。

## 05 未验证与已知边界

1. **WASAPI 未现场采音**：当前 PC 的 `PATH` 无 ffmpeg，`FfmpegLocator.resolve()` 返回 null，AAC 编码器无法端到端启动；COM 生命周期、事件回调、默认端点切换均只经编译与静态检查。
2. **音画同步未测**：PTS 已共用会话起点，但真实 30 分钟音画偏差、音频抖动/断续未测，不能替代 T06118/T06121。
3. **静音/音量未现场听感验证**：只验证了代码路径与单元测试的增益/静音输出。
4. **PC 音频能力边界**：若启动时 `audioCapable=false`（无 FFmpeg 或非 Windows），握手不会声明 `AUDIO_AAC`，且会话中途打开声音不会重建音频链路；当前 UI 未按能力隐藏/禁用“投送系统声音”，需在 T06115 现场验证时确认提示策略。
5. **T06119 仍受 T06118 阻塞**：中间件与接收端事件已落盘，但正式任务不因本次实现标记 T06118 完成；T06120 仍需按任务依赖推进。
6. **现场项统一转 T06115/T06121**：物理电视、Win11、真实音频设备与 30 分钟 soak 均未在本轮覆盖，不得写作通过。
