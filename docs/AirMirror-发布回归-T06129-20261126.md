## 1. 首次投屏成功率

方法：每次 `am force-stop` 接收端后冷启动 `ReceiverActivity`，读取当次 6 位投屏码，再启动 PC 客户端（1920×1080@30 / 8Mbps）连接，接收端 `metrics.received` 或 `session_end.received` > 0 记为成功。发送端 `[stats] frames=1` 只证明编码器出帧，不作为成功判据。

| 项 | 结果 |
| --- | --- |
| 尝试次数 | 20 |
| 严格首次成功 | 19 / 20 = **95.0%** |
| 失败尝试 | 第 6 次，投屏码 `168258`，首会话 `received=0`；客户端自动重连后另起会话成功 |
| 门槛 | ≥95%，**刚好达标** |
| 明细 | `assets/t06129-emulator-20261126/attempts-all.csv`、`attempt-1..20-pc.log`、`attempt-1..20-ui.xml` |

> 该轮 20 次尝试是在 **修复 1080p 焦点缺陷之前** 的 release 包上完成的，因此第 6 次的失败不应全部归因于 UI；它说明首次投屏链路仍有一次握手失败。修复包未再完成 20 次完整复测（本地执行环境中途掉线），发布门禁不能据此宣称稳定。

## 2. TV 截图矩阵与 1080p 缺陷

| 场景 | 证据 | 结果 |
| --- | --- | --- |
| 360dp 接收页 | `assets/t06129-emulator-20261126/receiver-720x1280.png` | 二维码、投屏码、设置入口完整，无截断 |
| 1080p 横屏接收页 | `assets/t06129-emulator-20261126/receiver-1920x1080-landscape.png` | 布局正常，无截断 |
| 1080p 横屏首页（修复前） | `assets/t06129-emulator-20261126/main-1920x1080-landscape.png` | **缺陷**：主按钮“投到其他设备”只剩上下两条青绿描边，文字不可见；UI 节点 `bounds=[61,414][1859,530]`、`clickable=true`，不是控件缺失 |
| 1080p 横屏首页（修复后，焦点在投屏） | `assets/t06129-emulator-20261126/main-1920x1080-fixed2-refocus.png` | 深蓝焦点底 + 青绿 2dp 描边，主按钮文字为亮色，可读 |
| 1080p 横屏首页（修复后，焦点移到接收） | `assets/t06129-emulator-20261126/main-1920x1080-fixed2-receive-focus.png` | 主按钮恢复品牌青绿底 + 深色字，失焦态可读；接收按钮获得焦点描边 |
| Robolectric 1080p 复验 | `assets/t06129-vm-20261126/t06129-main-1080p-focus-20261126.png`、`...primary-unfocused-20261126.png` | 自动断言首焦点文字 `TEXT_PRIMARY`、失焦恢复 `buttonPrimaryFg` 与 `buttonPrimaryBg`；6/6 通过 |

根因：`TvFocus.apply()` 在 TV 焦点态把 `backgroundTintList=null`，用 `outline()` 替换背景；但主按钮文字仍为 `buttonPrimaryFg = semantic.background`（深色），深色字落在深蓝半透明焦点底上不可读。720p 宽度 <1024 不进入 TV 模式，故不触发。

修复：焦点时对 `TextView` 使用 `Theme.TEXT_PRIMARY`；失焦恢复原 `textColors`。同时不再依赖 `MaterialButton.backgroundTintList` setter 的延迟重着色，直接对还原后的 `Drawable` 调 `DrawableCompat.setTintList`，避免 1080p 实测中主按钮退回黑色默认底。

验证：`TvFocusUiTest` 6 项 / 0 失败（`primaryButtonRestoresFillAndTextAfterFocusLeaves` + `mainEntryFollowsVisualChain` 覆盖焦点文字、失焦填色）；Robolectric 1080p 截图由测试生成。

## 3. 主题迁移差异

复用既有证据：`docs/AirMirror-主题令牌实现-20261123.md` 记录 17 组旧色/新令牌逐像素比对差异 **0**（要求 ≤1%），360dp / 1080p 预览均在 `assets/theme-tokens-20261123/`。本次 TvFocus 修复只改焦点态前景色与还原路径，未改主题令牌或普通态配色，不引入新的主题差异。

## 4. 关联需求与验收项

- REQ-011：API 22 下限 / Android 7–14 TV / Win10/11 / 30 分钟稳定运行。Android 14 模拟器验证通过；Win11、物理 TV、30 分钟 soak 未验证。
- AC-01：360dp / 1080p 无截断。模拟器 360dp、1080p 截图通过；物理电视 overscan、3 米可读未验证。
- AC-02：已信任 ≤10s 出帧、首次扫码 ≤15s 出帧。本轮批量尝试在第 1 帧统计后即结束，未形成可信 `first_frame` 事件；**不宣称通过**。
- REQ-018 / REQ-019 属 v2.1 的画质延迟 HUD 与 PC WGC 扩展，当前版本未实现；本任务只在回归矩阵中登记关联，不把“未实现”写成“通过”。

## 5. 边界与未验证

- 无物理 Android TV / 盒子、Win11、同网 mDNS 现场；T06115 仍阻塞。
- 无 FFmpeg，PC 端回退 JCodec，实测约 0.5–1.5 fps，不等于 1080p60 性能。
- 20 次成功率 19/20 是修复前包的严格首次结果；修复包只做了 UI 回归和单测，未重跑完整 20 次。
- 本地执行环境在修复包复测期间掉线，clean-run 只完成 2 次尝试且未取得 `metrics` 采样，不能作为最终成功率证据。
- 30 分钟 soak、A/V 偏差、DRM、真实 TalkBack 未验证；T06121 / T06130 仍阻塞。

## 6. 结论

T06129 的 1080p TV 焦点可用性缺陷已定位并修复，回归截图和 6/6 单测可复核；首次投屏在修复前包上达到 19/20（95.0%）的严格门槛，但处于边界且第 6 次存在真实握手失败。由于物理 TV、Win11、首次出帧计时和修复包完整 20 次复测缺失，**T06129 不能作为发布验收全部通过**，只能交付“回归记录 + 缺陷修复 + 本地 UI 证据”，发布门禁仍需 T06115 / T06121 / T06125 / T06128 / T06130 收口。
