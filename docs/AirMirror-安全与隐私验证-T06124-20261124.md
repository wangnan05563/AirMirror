## 02 本轮代码修复

问题：`BrowserCastServer` 的访客 token 在构造时生成，运行期间永久有效；此前只在进程重启时更换，不满足 REQ-010「访客 Token 5 分钟失效」。

改动：

- `app/src/main/java/io/github/wangnan05563/airmirror/web/BrowserCastServer.kt`
  - 新增 `tokenTtlMillis`（默认 `DEFAULT_TOKEN_TTL_MS = 5 * 60_000L`）与可注入 `now`，便于测试推进时钟。
  - 新增 `activeToken` / `tokenIssuedAt`；`currentToken()` 到期后在锁内换新，避免并发请求换出两枚 token。
  - `url()`、`tokenMatches()`、`pagePath`、`uploadPath` 全部改为读取 `currentToken()`。
  - `start()` 重置 token 签发时间；旧 URL 到期即 404，页面旧表单必须刷新后才能上传。
- `app/src/test/java/io/github/wangnan05563/airmirror/web/BrowserCastServerTest.kt`
  - 新增「五分钟到期后自动换新且旧地址立即 404」。
  - 新增「到期旧 token 的上传路径 404 且不产生文件」。

未改其他业务代码。待连接页 `ReceiverActivity.refreshBrowserRow()` 每 500ms 调 `host.browserCastUrl()`，URL 变化时重画二维码；因此服务端换 token 后，大屏有承接路径。

## 05 未验证与边界

1. **真实浏览器 5 分钟等待未验**：测试用注入时钟推进到 4:59.999 / 5:00.000，HTTP 走 127.0.0.1 真实套接字；没有在物理电视/真实浏览器上等 5 分钟观察二维码自动换新。
2. **PIN 跨重启是 JVM 跨实例**：`PinCodeTest` 用同一份落盘字符串新建实例，等价于进程重建；没有在真实电视上断电/重启复验。
3. **撤销后「1 秒内断开」未用仪器测**：代码路径是同步调用 `host.endActiveSession()`，TrustRegistry 单测只证明活动会话被释放；实际视频/音频 socket 关闭耗时未测。
4. **30 天过期用注入时钟**：没有真实等待 30 天，也没有跨真实系统时间调整的边界样本。
5. **无账号/云是静态扫描结论**：没有做完整网络抓包；GitHub Release 更新检查是用户可触发的元数据请求，不携带账号。
6. **真机 UI 未验**：浏览器地址行/二维码刷新在 500ms ticker 上，只有代码路径与 JVM 服务测试；TV 上的实际刷新视觉未截图。
7. **Robolectric 清理告警**：全量末尾出现临时目录 `fonts` 非空告警，测试任务仍 `BUILD SUCCESSFUL`、927 项 0 失败；属测试框架清理抖动，未据此宣称产品异常。
8. **局域网 HTTP 明文**：访客页与上传走 `http://<ip>:<port>/w/<token>/`，token 在 URL 中；同网嗅探者可截获，5 分钟 TTL 只缩短暴露窗口。当前未做 TLS 或单次上传令牌，属后续安全加固项。

## 06 结论

- **访客 Token 5 分钟失效：已从缺口变为实现**。旧 token 到期即 404，新 token 由 `url()` 自动换新；上传路径同样拒绝。
- **PIN 锁定跨重启、30 天未用、撤销信任释放活动会话、日志脱敏：代码与单测证据齐全**。
- **T06124 可作为代码级完成收口**；AC-05 的真机现场项（断电、1 秒断流、真实 5 分钟）仍需在 T06115/T06128 环境补测，不能把 JVM 测试写成端到端通过。
