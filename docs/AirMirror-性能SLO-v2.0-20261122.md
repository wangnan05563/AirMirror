# AirMirror 性能 SLO 与验收口径 v2.0（T06116 / REQ-009）

| 项 | 内容 |
| --- | --- |
| 任务 | T06116 [PRD] 定义性能 SLO 指标 |
| 需求 | REQ-009：统一本地埋点；首帧 ≤3s；P95 延迟 ≤200ms（5GHz）；1080p60 丢帧 ≤1%；APK 增量 ≤2MB |
| 验收 | AC-09：A/B/C 级 30 分钟 soak 通过；首帧/延迟/内存指标达标；门禁通过 |
| 基线 | HEAD `1ed55fc`；release APK 5,338,905 B；已有 `体验指标验证方案` 与部分 JVM 门禁 |
| 产物性质 | SLO 口径、测量方法与门禁；不实现埋点代码，供 T06119/T06120/T06121 实施 |

## 01 结论先行

1. SLO 分两档：**5GHz/有线**按 REQ-009 原值；**2.4GHz**单独放宽，避免把物理层限制误判为产品退化。
2. 固定 6 个核心指标：首帧、重连、P95 延迟、1080p60 丢帧、内存、APK 增量；另加 2 个诊断指标：音画差、CPU。
3. 所有指标在**接收端**打点，时间基准用 `SystemClock.elapsedRealtimeNanos()`；发送端只记录请求与首帧到达，禁止跨设备用墙钟直接相减。
4. 每项指标都给出采样窗口、样本量、百分位算法和判定条件；不达标必须能定位到采集点与设备等级。
5. soak 固定 30 分钟，A/B/C 各级至少 1 台；每 5 分钟采一次 PSS/CPU/温度，结束后统计斜率与峰值。
6. APK 增量以 001 debug 包为基线的可比口径；当前 002 release 包 5.34MB，若以 001 6.60MB 比是下降，不能拿不同构建类型直接比较。

## 02 设备分级与网络档

| 档 | 代表设备/网络 | 角色 | 说明 |
| --- | --- | --- | --- |
| A | 旗舰手机 + 5GHz + 中高端电视 | 主验收 | 1080p60、4K30 条件验收 |
| B | 中端手机 + 5GHz + 主流电视 | 主验收 | 1080p30/60 动态档 |
| C | 低端手机/老电视 + 2.4GHz | 兜底验收 | 720p30 或 1080p30 低码率 |
| W | Windows PC 有线/Wi-Fi 5GHz | 扩展验收 | PC 发送端 1080p30 |

网络档判定不只看 SSID：以 `WifiManager` 的 frequency/链接速率 + 实测 RTT 为准；有线 PC 单独标记 `WIRED`。

## 03 指标定义

### 3.1 首帧时间（First Frame）

- **起点**：用户点击“开始投屏”/“连接”的 `ACTION_DOWN` 时刻。
- **终点**：接收端第一帧解码完成并提交到渲染面（`onFrameAvailable` 或首帧上屏回调）。
- **口径**：端到端，包含握手、鉴权、编码器启动、首帧传输、解码。
- **目标**：
  - A/B 5GHz：P50 ≤1.5s，P95 ≤3.0s。
  - C 2.4GHz：P50 ≤2.5s，P95 ≤5.0s（标注为放宽档，不计入 REQ-009 主目标）。
  - W 有线：P95 ≤3.0s。
- **样本**：每设备每网络档 ≥20 次冷启动投屏；去掉首次安装后的 1 次，避免 dex/缓存干扰。

### 3.2 重连时间（Reconnect）

- **起点**：接收端连续 3 个心跳未收到，判定断线。
- **终点**：重连后首帧重新上屏。
- **目标**：A/B ≤3s；C ≤6s；30 秒内未恢复判定失败并结束会话。
- **样本**：每设备 ≥10 次，断网方式包括拔网线/关 Wi-Fi/切换 AP。

### 3.3 P95 延迟（Glass-to-Glass）

- **定义**：发送端画面变化 → 接收端上屏的端到端延迟；用画面内时间码/闪烁标记法测，不用系统时钟差。
- **目标**：5GHz/有线 P95 ≤200ms；2.4GHz P95 ≤350ms（放宽档）。
- **采样**：1080p60 连续 5 分钟，每秒 ≥1 个标记，共 ≥300 个样本；P95 用最近秩法。
- **附加**：音画差 ≤80ms 为优，80–150ms 为可接受，>150ms 触发“正在重新对齐”；连续 3 次仍超 150ms 提示兼容模式。

### 3.4 丢帧率（Dropped Frame）

- **定义**：接收端渲染丢帧数 / 发送端有效视频帧数；不含主动降档丢弃的帧。
- **目标**：A/B 1080p60 ≤1%；1080p30 ≤0.5%；C 720p30 ≤3%。
- **采样**：连续 10 分钟，每 10 秒窗口统计一次；整段加权平均。
- **判定**：同时看整段和 P95 窗口，避免平均达标但周期性卡顿。

### 3.5 内存（PSS）

- **定义**：接收端进程 PSS；Android `dumpsys meminfo`，PC 用 Working Set。
- **目标**：投屏 30 分钟后 PSS ≤投屏前 +80MB；无单调增长（最后 10 分钟斜率 ≤2MB/min）。
- **采样**：每 5 分钟一次，记录 Java heap/native/graphics。
- **告警**：单次增长 >40MB 或 OOM 前 5 分钟增长 >10MB/min 即失败。

### 3.6 APK 增量

- **定义**：同渠道、同签名、同构建类型的相邻版本 APK 体积差；首次以基线包为参照。
- **目标**：单版本增量 ≤2MB；release 包不得因新增资源突破 8MB 硬顶（当前 5.34MB）。
- **采集**：`Get-FileHash`、`aapt dump badging`、`apksigner verify`；记录未压缩/压缩后大小。
- **注意**：debug 与 release 不可直接比较；001 debug 6.60MB 与 002 release 5.34MB 的差值不是“优化 1.26MB”的发布结论。

### 3.7 CPU 与温度（诊断项，不阻断）

- 接收端 CPU 占用量：1080p60 ≤35%（A/B），≤50%（C）。
- 电池温度/机身温度：30 分钟 soak 后 ≤45°C；超过记录不作为单独失败项，但需在报告中说明降档。

## 04 埋点事件

统一本地 JSONL，不上传；字段：

```json
{
  "event": "cast_first_frame",
  "session_id": "uuid",
  "device_tier": "A|B|C|W",
  "network": "WIRED|5G|2.4G",
  "resolution": "1920x1080",
  "fps": 60,
  "t_request_ns": 123456789,
  "t_first_frame_ns": 123458589,
  "first_frame_ms": 1800,
  "p95_latency_ms": 182,
  "dropped_frames": 12,
  "total_frames": 18000,
  "pss_kb": 182400,
  "cpu_pct": 28.4,
  "av_diff_ms": 42,
  "cause": null
}
```

约束：

- `session_id` 随机 UUID，不含设备名/IP/投屏码。
- 时间用 `elapsedRealtimeNanos`，跨设备只比较同一会话内相对时间。
- 事件写入失败不影响投屏；本地最多保留 7 天/10MB，滚动删除。
- 诊断页只读展示最近 20 条；导出时脱敏。

## 06 门禁与报告

- **G1 合并门禁**：SLO 事件 schema 单测、字段脱敏测试、P95 算法测试、APK 体积守卫。
- **G2 发布门禁**：A/B 各 1 台 + C 1 台完成 SLO-01~11；缺一台则 release 标记“有条件通过”。
- **G3 记录**：每次 release 附 `docs/assets/slo-<version>/report.json` 与 soak 截图/日志。
- **失败处置**：任一主指标不达标，先定位是网络档、设备档、编码档还是实现退化；不得用“平均达标”掩盖 P95 失败。
- **回滚线**：release 后首帧 P95 回退 >30%、丢帧 >2 倍或崩溃率 >0.5%，触发回滚/热修。
