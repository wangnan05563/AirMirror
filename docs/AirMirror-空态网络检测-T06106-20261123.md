# AirMirror 空态网络检测 T06106（2026-11-23）

## 目标与边界

T06106 按 PRD FR-2.0-01 / REQ-001、REQ-018 实现发送端空态的四类状态判定，只交付检测服务和诊断数据接口，**不在本单新增页面或改动空态视觉**；空态卡片的最终接线由后续回归/页面任务承接。

| 状态 | 判定 | 稳定码 | 建议动作（由 `ErrorNotice` 提供） |
| --- | --- | --- | --- |
| 未联网 | 没有 Wi-Fi/有线/移动/其他可用链路 | `AM-NET-04` | 去设置、重试发现 |
| 同网无接收端 | 有链路，15 秒内没有发现接收端 | `AM-ND-02`；已知设备全离线用 `AM-OFF-01` | 重试发现、用投屏码、手动输 IP |
| 配对失败 | 已发现接收端且最近一次配对失败 | `AM-PAIR-01` | 重试、换投屏码 |
| 网络策略限制 | AP 隔离、双频分离、VPN/企业策略 | `AM-NET-01` / `AM-NET-02` / `AM-PERM-01` | 重试发现、用投屏码、手动输 IP |

判定优先级：**未联网 → AP 隔离/双频 → 平台策略 → 配对失败 → 在线/READY → 15 秒窗口内继续搜索 → 无接收端**。已存在在线接收端或发现判决为 `Found` 时返回 `READY`，页面不需要空态。

## 诊断数据接口

`EmptyNetworkCheck.Snapshot` 是调用方输入，只包含：

- `link`：`NONE/WIFI/ETHERNET/MOBILE/OTHER`；
- `localIp`：本机 IPv4，可空；
- `foundReceivers`：本次扫描发现的接收端数量；
- `lastScanAt`：最近扫描的单调时钟时间；
- `platformRestricted`：仅明确知道 VPN/企业策略时置真。

**不包含 SSID/BSSID**。`NetworkDiagnostics` 用 `ConnectivityManager.activeNetworkInfo` 和 `NetworkInterface` 枚举地址，不读 Wi-Fi 名称，因此不新增位置权限；通知/录音权限也不参与发现，不会被误判为“权限导致搜不到”。

`EmptyNetworkCheck.Result` 返回 `state`、`cause`、`actions`、`code` 与 `diagnostic`；`diagnostic.elapsedMs` 是同一时钟下的扫描耗时。页面只需消费结果，不重复拼状态文案。

## 时间与重试

- `NO_RESULT_TIMEOUT_MS = 15_000L`：不足 15 秒只返回 `SEARCHING`，不提前断言“没有接收端”；15 秒整进入 `NO_RECEIVER`。
- `AUTO_RETRY_MS = 5_000L`：`retryDue(now, lastScanAt)` 每 5 秒允许一次自动重试；时钟回拨也允许重试，避免旧时间戳卡死。
- 自动重试的启动/停止仍由页面或扫描器控制；本单只提供节奏判定，不启动后台线程。

## 现场注意事项

- `activeNetworkInfo` 在 Android 10+ 标记 deprecated，但仍可读取链路类型；只用于诊断，不参与连接决策。
- 移动网络（`MOBILE`）只代表有链路，不代表同网可发现；页面应显示“没有发现接收端/网络策略”而不是“未联网”。
- 企业 VPN、AP 隔离、双频分离都归 `RESTRICTED`；运行时通知/录音权限不阻塞发现，不能混入该状态。
