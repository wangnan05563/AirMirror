## 01 交付边界

本轮把 T06101 的 `ErrorStateCard` 从“可单测组件”接入发送端页面，并补齐首次连接加载态：

| 交付 | 文件 | 说明 |
| --- | --- | --- |
| 错误/空态卡接入 | `SenderActivity.kt` | `diagnosisCard` 由 `LinearLayout` 换成 `ErrorStateCard`；三套插画、稳定错误码、原因/下一步、固定三动作统一由组件渲染 |
| 加载卡 | `LoadingStateCard.kt` | 设备名 + 系统进度 + 代码骨架 + 10 秒后取消；组件只回调宿主 |
| 加载骨架 | `LoadingSkeletonView.kt` | 三条圆角占位条 + 扫光，全部 Canvas 绘制，不读位图 |
| 搜索中空态 | `SenderActivity.renderEmptyState()` | 搜索窗口未结束且 0 台时显式绑定 `NO_DISCOVERY`，不再只留一行提示 |
| 无障碍文案 | `A11yCopy.loadingCancel()` | 取消按钮的可访问名 |
| 回归守卫 | `SenderEmptyStateUiTest.kt`、`EmptyDiagnosisGuardTest.kt`、`AccessibilityManifestTest.kt`、`CompactPagesRenderTest.kt` | 页面截图、组件断言、动作循环与接线点计数同步 |

不改 `EmptyDiagnosis.of` 的判决优先级与 `EmptyDiagnosis.ACTIONS` 的固定顺序；不改 `ErrorNotice` 文案表；不在页面拼异常类名或堆栈。

## 02 空态接入

### 2.1 判决链路保持单源

```
DiscoveryLadder.verdict + DeviceRegistry.emptyReason
        ↓ EmptyDiagnosis.of（不变）
ErrorNotice.Cause?
        ↓
ErrorStateCard.bind(cause, EmptyDiagnosis.ACTIONS)
        ↓
插画（按 Scene）→ 错误码 → 原因 → 下一步 → 主/次/兜底
```

- `cause != null`：直接 `bind(cause)`，由 `ErrorVisualSpec.sceneFor` 选三套插画，`codeFor` 出稳定码。
- `cause == null` 且 `verdict` 仍是 `SEARCHING`、`emptyReason == NONE_FOUND`、列表 0 项：显式 `bind(NO_DISCOVERY, EmptyDiagnosis.ACTIONS)`，保证搜索中也有可执行入口。
- 已命中设备、已有在线设备或列表非空：保持原有提示/隐藏逻辑，不强行套错误卡。
- `ErrorStateCard` 的 `onAction` 绑定宿主的 `onDiagnosisAction`：重试发现、聚焦投屏码、聚焦 IP，均为当前页就地动作。

### 2.2 360dp 紧凑适配

原 `ErrorStateCard` 的 120dp 插画 + 竖排三按钮在 360×640 页面会被底部固定输入区裁掉第三枚按钮。T06104 按 `screenHeightDp < 700` 启用紧凑视觉：

| 项 | 非紧凑 | 紧凑 |
| --- | --- | --- |
| 插画 | 200×120dp | 120×72dp |
| 错误码字号 | 12sp | 11sp |
| 下一步字号 | `FocusPolicy.bodySp` | `Theme.PHONE_BODY_SP` |
| 动作区 | 竖排 48dp/枚 | 横排等宽 48dp/枚 |
| 卡内间距 | 8dp | 4dp（错误码上边与动作区上边） |

`CompactPagesRenderTest` 与 `SenderEmptyStateUiTest` 双重检查“用投屏码连接”按钮完整落在 360×640 可视区（`getGlobalVisibleRect` 高度不小于按钮高度），不是只看坐标。

## 03 加载态

### 3.1 状态机

```
用户点设备/输码/直连
  → connectTo / connectCrossNet
  → beginLoading(设备名)       // 显示加载卡，隐藏诊断卡
  → 权限说明 / 录屏授权
  → CaptureService 启动
  → 首帧 quality 非空 或 报错
  → endLoading()               // 隐藏加载卡；空列表恢复诊断卡
```

- **10 秒前**：`ErrorVisualSpec.loading(name, elapsedMs)` 返回“正在连接<设备>…”，取消按钮 `GONE`；骨架持续扫光。
- **10 秒整起**：同一函数返回“仍在连接<设备>…”，取消按钮 `VISIBLE`，文案提示“电视端可能未响应；可取消后检查网络，或改用投屏码连接。”
- `loadingTimeout` 只在 10 秒到点重绑一次文案，不做每秒重绘；离开页面时 `removeCallbacks`。
- `endLoading` 由三类事实触发：`SenderReport.last` 非空（报错）、`SenderReport.quality` 非空（首帧到）、状态切 `IDLE/ERROR`。`CASTING` 仅表示服务已起，不提前收起加载卡，避免“服务已起但画面没到”的空白。
- 取消：清 `pending`、`pendingTarget`、跨网 token；若录屏授权已通过（`captureStarted`），向 `CaptureService` 发 `ACTION_STOP`；恢复输入框并回到 idle。
- 连接代次 `connectGeneration`：取消或发起新连接后，上一轮跨网打洞晚到的结果直接关闭隧道并丢弃，不弹授权、不起服务。

### 3.2 组件 API

```kotlin
val card = LoadingStateCard(context)          // compact 按 screenHeightDp 自动判定
card.bind(deviceName, elapsedMs)              // 文案/取消显隐
card.onCancel = { ... }                       // 宿主清理连接
card.visibility = View.VISIBLE / GONE
```

`LoadingSkeletonView` 在附着窗口且可见时按 `SystemClock.uptimeMillis()` 推进扫光相位，并用 `postInvalidateOnAnimation()` 逐帧刷新；不可见/离窗立即停止，不引入 `ValueAnimator`/`ObjectAnimator` 等动画框架（与 `CodeFadeGuardTest` 的“UI 层不引入属性动画框架”守卫一致）。`A11y.decorative` 从无障碍树移除，真实状态由加载卡标题（`A11y.liveStatus`）承载。
