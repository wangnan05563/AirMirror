| UI 点击与投屏码读取 | `ui_tap.js`（`--read` 读码；三连授权文案见下） |

**必须记住的假绿陷阱**（每一条都曾经骗过我一次）：

1. adbd 会把 `am start … --es …TARGET_CREDENTIAL <6位>` 整行记进 logcat → **每条腿收口都要跑一次 `TARGET_CREDENTIAL (\d{6})` 打码**，正则要允许尾随单引号。
2. 空 UI dump 和桌面 launcher 的 dump（都是 21828B）都能过体积门 → 必须重试到 >1000B **且** `grep -q nexuslauncher` 为空。
3. `pm clear` 后立刻 `am start` 会被系统异步 `remove task` 吃掉 → 以 `mCurrentFocus=.*<全限定类名>` 为判据反复拉起，重试用裸 `am start`。
4. 后台任务通知里的 exit code 不可信 → 编译/测试结论一律看输出文件与 test-results XML。
5. 测 DLNA/播放必须先证明播放器真在推进：接收端在后台时 Surface 已销毁，纯视频会停在 `00:00:00` 且不报错，看起来像回归其实是环境。
6. 起测前把日志清零（`logcat -c`），判据只读 `AirMirrorReceiver|AirMirrorCapture|AirMirrorProbe` 三个 TAG；`ANSI` 色码会让锚定 grep 假报 0 命中。
7. MediaProjection 授权链在 API 37 是 `Share one app` → `Share entire screen` → `Share screen`；`uiautomator find` 式的 clickable 匹配点不动 Spinner，要用 `ui_tap.js`。
8. 端口纪律：14523/14524/14701 归历史 adb forward 规则（端口由 adb server 持有），`adb reverse` 16000/16100 属别的腿——新腿用 14700/14701/16100 之外的干净端口，别动别人的。
